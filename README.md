# Учёт муниципального имущества

Локальное приложение для учебной практики. Дашборд показывает поступления, просроченную задолженность, актуальный реестр и договоры на продление. В реестрах можно добавлять и редактировать объекты и договоры. Раздел «Финансы» хранит начисления, частичные платежи и историю оплат.

## Запуск в Windows

Откройте терминал PowerShell в корне проекта, в том числе через **WebStorm → Terminal**. Для запуска нужны Python 3.12 или новее и запущенная служба PostgreSQL 15.

### 1. Окружение и подключение

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Команды вызывают Python напрямую, поэтому активировать окружение и менять PowerShell Execution Policy не требуется. При использовании конфигурации запуска WebStorm выберите `.venv\Scripts\python.exe` как интерпретатор.

Используйте существующий `.env`. Для нового рабочего каталога скопируйте пример и задайте пароль локальной роли, если файла ещё нет.

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
    notepad .env
}
Get-Service postgresql-x64-15
```

Стандартное подключение использует `localhost:5432`, базу `municipal_property` и роль `municipal_user`. Приложение проверяет имя базы и считывает пароль из окружения или `.env`. Пароль со специальными символами передаётся драйверу как отдельный параметр.

Если на другой машине проектная база или роль ещё отсутствуют, выполните следующие команды в `psql` под локальным администратором PostgreSQL. Выполняйте `CREATE ROLE` и `CREATE DATABASE` только для отсутствующей роли или базы. Команда `\password` считывает пароль интерактивно. Существующий пароль менять не нужно.

```powershell
& "$env:ProgramFiles\PostgreSQL\15\bin\psql.exe" -U postgres -d postgres
```

```sql
CREATE ROLE municipal_user LOGIN;
\password municipal_user
CREATE DATABASE municipal_property OWNER municipal_user;
\q
```

Для имеющейся базы подготовка требует прав роли на создание таблиц в `public`. Интеграционные тесты дополнительно требуют права `CREATE` на уровне `municipal_property` для временных схем.

### 2. Схема, демонстрационные данные и сервер

```powershell
.\.venv\Scripts\python.exe -m backend.init_db
.\.venv\Scripts\python.exe -m backend.seed
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

[Открыть приложение](http://127.0.0.1:8000/) · [Документация REST API](http://127.0.0.1:8000/docs)

`init_db` создаёт отсутствующие таблицы и подходит для повторного запуска. Для существующей базы выполните аудит и миграцию реквизитов по инструкции ниже. Если в ней ещё есть поле `counterparties.contact`, сначала обновите реестр контрагентов. Chart.js входит в локальные ресурсы приложения. Просмотр диаграмм работает без интернета.

### 3. Миграция существующего реестра контрагентов

Остановите FastAPI перед миграцией. Для существующей базы выполните аудит и примените миграцию с проектными настройками из `.env`.

```powershell
.\.venv\Scripts\python.exe -m backend.migrate_counterparty --audit
.\.venv\Scripts\python.exe -m backend.migrate_counterparty --apply
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Миграция работает в `public` проектной базы. Перед правкой она создаёт полный локальный архив в `backups/`, проверяет его через `pg_restore` и записывает SHA-256. Утилиты PostgreSQL ищутся в стандартной папке установки PostgreSQL 15. Для другой папки укажите `--pg-bin`.

В одной транзакции `contact` переименовывается в `email`, корректные адреса переносятся с обрезкой крайних пробелов, пустые и неподходящие значения становятся `NULL`. Исходные значения доступны в архиве. Для `tax_id` устанавливаются `NOT NULL`, `UNIQUE` и `CHECK` на 10 или 12 цифр. Автоматическая замена 13-значного номера требует точного совпадения имени, старого номера и синтетического адреса с прежним каталогом. Неизвестный некорректный ИНН или конфликт среди итоговых номеров останавливает миграцию. При ошибке PostgreSQL отменяет транзакцию. Повторный запуск на обновлённой схеме завершается без изменений.

Стандартный Swagger UI на `/docs` загружает свои ресурсы через CDN. Схема `/openapi.json` выдаётся локальным сервером.

Списки с оформленными вариантами и плавным открытием и закрытием доступны в браузерах с поддержкой `appearance: base-select`. В остальных браузерах используется системный список. Интерфейс учитывает настройку уменьшенного движения.

### 4. Аудит ИНН и миграция кадастровых номеров

Для существующей базы остановите FastAPI, проверьте отчёт аудита и выполните миграцию.

```powershell
.\.venv\Scripts\python.exe -m backend.migrate_requisites --audit
.\.venv\Scripts\python.exe -m backend.migrate_requisites --apply
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Аудит читает все записи `public`, включая архивные объекты, и проверяет определение установленного кадастрового `CHECK`. Перед изменениями `--apply` создаёт полный архив в `backups/`, проверяет чтение через `pg_restore` и сохраняет SHA-256. В одной транзакции миграция заменяет прежний `CHECK`, сохраняет существующий `UNIQUE` и добавляет уникальный индекс для сравнения эквивалентных записей. Ограничения ИНН PostgreSQL действуют вместе с проверкой контрольных цифр в API.

Автоматическая коррекция ИНН доступна при точном совпадении имени, прежнего ИНН и синтетической почты с каталогом. Неподтверждённые ИНН, неверный формат кадастрового номера или конфликт, в том числе между разными написаниями одного номера, останавливают применение до записи. Сверьте записи по идентификаторам из отчёта и повторите аудит после согласованных исправлений. После успешного обновления повторный запуск возвращает `current`.

## Сквозная проверка через интерфейс

1. В «Объектах» добавьте объект. При необходимости заведите контрагента в отдельном реестре «Контрагенты». В «Договорах» выберите эти записи и создайте действующий договор со сроком окончания через 20 дней.
2. В «Финансах» добавьте начисление на 1 000 ₽ по этому договору. Укажите прошлые даты начисления и срока оплаты, чтобы проверить просрочку.
3. Откройте начисление и зарегистрируйте платёж на 300 ₽ сегодняшней датой. В карточке отобразятся история оплаты и остаток 700 ₽.
4. Вернитесь на «Дашборд». Сравните значения с состоянием перед операциями. Доходы вырастут на 300 ₽ за период, в который входит платёж. Просрочка по начислению после платежа составит 700 ₽. Действующий договор добавит 1 к KPI продления.
5. Выбирайте карточки мышью или клавишами Tab и Enter. В каждом режиме меняются заголовки, данные и обе диаграммы. Наведите указатель на точку графика, чтобы увидеть значение.

## Объекты, договоры и начисления

- **Объекты.** Для неархивированного объекта статус «Используется» вычисляется по фактически действующим договорам аренды земли или недвижимости. Без такой аренды объект «Свободен». Карточка и фильтры используют вычисленный статус. Архивирование доступно после прекращения действующих и ожидающих начала договоров всех типов. Восстановление запускает обычный расчёт статуса при чтении. API использует `PATCH /api/properties/{id}` со значением `archived` для архивирования и `available` для восстановления.
- **Договоры.** Интерфейс показывает фактический «Статус договора». Хранимый `status = active` означает, что договор административно открыт. Для открытого договора дата начала в будущем даёт «Ожидает начала», прошедшая дата окончания – «Срок истёк», остальные случаи – «Действует». Первый и последний дни входят в срок действия. Завершение и расторжение имеют приоритет над датами. В API параметр `state` фильтрует фактический статус, а `status` – хранимый.
- **Архивные связи.** Архивный объект нельзя выбрать для нового договора или переноса. Изменение статуса или дат старого договора, которое сделает его действующим или ожидающим начала, требует восстановления объекта. Историческая связь и финансовые записи доступны при просмотре. Для ранее сохранённой несовместимой пары доступны правки справочных полей и завершение договора, а активация и продление требуют исправления пары.
- **Совместимость.** Аренда земли допускает только земельные участки, аренда недвижимости – здания и нежилые помещения. Продажа и прочие договоры допускают все категории. Категорию объекта можно изменить после завершения или расторжения несовместимых связанных договоров. Для договора со статусом записи `active` и истёкшей датой окончания сначала завершите его вручную.
- **Начисления и платежи.** Начисление можно изменить или удалить, пока у него нет платежей. Из истории начисления можно открыть карточку платежа, исправить его сумму и дату или удалить запись с подтверждением. Для переноса платежа на другое начисление удалите ошибочную запись и создайте новую по нужному начислению. Допустимая дата лежит между датой начисления и сегодняшней датой включительно. Максимальная сумма при редактировании равна сумме начисления за вычетом других платежей. Прежние платежи с будущими датами остаются в истории и резервируют остаток. В оплаченные суммы, доходы и просрочку они входят с даты поступления.

### Проверка форм и API

| Форма | Правила |
| --- | --- |
| Объект | Обязательны наименование до 200 символов, категория из списка и адрес до 300 символов. Площадь и примечание до 3000 символов необязательны. Кадастровый номер до 80 символов уникален по всему реестру. Пустое значение хранится как `NULL`. |
| Контрагент | Обязательны наименование до 200 символов и уникальный ИНН. ИНН хранится строкой с ведущими нулями. После удаления пробельных символов и дефисов проверяются 10 или 12 ASCII-цифр, контрольные цифры и наличие хотя бы одной ненулевой цифры. Email необязателен, при заполнении проверяются формат и длина до 250 символов. |
| Договор | Обязательны уникальный номер до 80 символов, тип из списка, объект, контрагент и дата начала. Дата окончания обязательна для всех типов, кроме продажи, с учётом ограничений редактирования действующих договоров. Она не предшествует дате начала. Сумма и примечание до 3000 символов необязательны. |
| Начисление | Обязательны существующий договор, сумма, дата начисления и срок оплаты. Срок оплаты не предшествует дате начисления. Описание необязательно, до 3000 символов. |
| Платёж | Обязательны существующее начисление, сумма и дата от даты начисления до сегодняшнего дня включительно. Сумма ограничена доступным остатком. При правке предел учитывает исходную сумму редактируемого платежа. |

Крайние пробелы текстовых реквизитов удаляются. Площадь и суммы принимают точку или запятую, должны быть положительными и помещаться в `NUMERIC(14, 2)`: до 12 цифр целой части и до двух дробных. API отклоняет лишнюю точность, `NaN` и бесконечность. Символы пунктуации допустимы в наименованиях, адресах, номерах договоров и многострочных примечаниях.

Типовой кадастровый номер использует две цифры округа, две цифры района, 6 или 7 цифр квартала и положительный номер объекта без ведущих нулей. Группы ASCII-цифр разделяются двоеточиями. Для специальных территорий допустимы общероссийский префикс `0:0:0` и региональные нулевые кварталы, например `74:36:0:125` и `74:0:0:125`. При проверке уникальности ведущие нули групп не учитываются, поэтому `74:36:0703001:125` и `74:36:703001:125` конфликтуют. В базе сохраняется введённое написание после обрезки крайних пробелов. [Правила присвоения Росреестра](https://www.consultant.ru/document/cons_doc_LAW_450482/0fe6cd0d8506396d3048480735306b9a83c3b862/) · [Описание XML](https://sudact.ru/law/prikaz-rosreestra-ot-10072023-n-p0251-o/prilozhenie-n-1/opisanie/4/)

Проверки кадастрового формата и контрольных цифр ИНН выполняются локально. Подтверждение существования объекта требует сведений ЕГРН, а подтверждение регистрации налогоплательщика – сведений ФНС.

Звёздочка обозначает обязательное поле. Проверка запускается кнопкой «Сохранить» или клавишей Enter. Сообщения выводятся под полями с доступной связью через `aria-describedby`. Ошибки всей операции выводятся в общем блоке, черновик остаётся открытым. API возвращает локализованный массив `detail` для ошибок запроса. Для конфликтов отдельных полей сохраняется строковый `detail` и добавляется массив `errors` с расположением сообщения.

### Поиск, окна и страницы

- Для выбора объекта, контрагента или договора начните вводить запрос в самом поле. Поле ищет на сервере и подгружает следующие результаты при прокрутке. Стрелки перемещают выделение, Enter выбирает, Escape закрывает список. Кнопка × очищает выбранную запись.
- Карточки и окна подтверждения закрываются крестиком, кликом по фону или Escape. Для изменённой формы приложение предложит продолжить редактирование или выйти без сохранения. Отмена закрытия сохраняет черновик. Во время сохранения форма заблокирована.
- Основные реестры имеют синхронные номера страниц над и под таблицей. Нижние кнопки плавно прокручивают к началу таблицы, верхние сохраняют позицию. При загрузке остаются видимыми предыдущие строки. Настройка уменьшенного движения отключает анимации и плавную прокрутку.

### API платежей

| Метод | Назначение |
| --- | --- |
| `GET /api/payments/{id}` | Сумма, дата, начисление, номер договора и предел суммы для редактирования |
| `PATCH /api/payments/{id}` | Изменение `amount` и/или `payment_date` |
| `DELETE /api/payments/{id}` | Удаление одного платежа |

Существующие регистрация и список платежей сохраняются. Сервер блокирует строку начисления перед регистрацией, изменением или удалением платежа. При переплате возвращается HTTP 409, при неверных данных – HTTP 422, а для отсутствующего платежа – HTTP 404. Доходы и задолженность пересчитываются по фактическим строкам, в том числе после переноса платежа в другой месяц или год.

### Жизненный цикл договора

При создании API выставляет `status = active`. Прошедшие даты начала и окончания подходят для внесения договора с истёкшим сроком. Обычное редактирование позволяет менять даты ожидающего договора. У действующего договора изменённые даты должны оставлять его действующим, а перенос даты окончания вперёд доступен только через «Продлить».

| Статус договора | Доступные действия |
| --- | --- |
| Ожидает начала | Редактировать |
| Действует | Редактировать, завершить, расторгнуть, продлить действующую аренду с датой окончания |
| Срок истёк | Изменить примечание, завершить, создать новый договор на основе |
| Завершён | Создать новый договор на основе |
| Расторгнут | Создать новый договор на основе |

«Завершить» и «Расторгнуть» требуют подтверждения и сохраняют даты. «Продлить» изменяет только дату окончания действующей аренды. Дата должна быть строго позже текущей даты окончания. Во всех случаях начисления и платежи остаются у исходного договора. Карточка содержит список начислений, из которого можно открыть историю платежей и зарегистрировать оплату по старой задолженности.

При создании на основе старого договора форма подставляет тип, объект, контрагента, сумму и ссылку на номер предыдущего в примечании. Укажите новый уникальный номер и новый период. Для истёкшего договора новый период должен начинаться после старой даты окончания. Для уже завершённого или расторгнутого договора прежняя плановая дата окончания новый период не ограничивает. Сервер создаёт новый договор и закрывает истёкший в одной транзакции. Начисления и платежи остаются привязаны к прежней записи. Для продажи и прочих типов получается самостоятельная сделка.

#### Методы API

| Метод | Назначение |
| --- | --- |
| `POST /api/contracts` | Создание договора. Хранимый статус присваивает сервер |
| `PATCH /api/contracts/{id}` | Правка по правилам выше. Поле `status` отсутствует в теле запроса |
| `POST /api/contracts/{id}/complete` | Завершение |
| `POST /api/contracts/{id}/terminate` | Расторжение |
| `POST /api/contracts/{id}/extend` | Продление. Тело запроса содержит только `end_date` |
| `POST /api/contracts/{id}/successor` | Создание нового договора. Тело запроса такое же, как при обычном создании |

Для завершения и расторжения тело запроса не нужно. Недоступное для текущего статуса действие возвращает HTTP 409. Некорректные данные, включая попытку передать `status` при создании или правке, возвращают HTTP 422.

## Правила расчёта

- Дата среза берётся в часовом поясе `Asia/Yekaterinburg`. Год в блоке доходов меняет только поступления на карточке и обеих диаграммах доходов. По умолчанию выбран текущий год, остальные годы доступны при наличии платежей. Столбцы показывают отдельные месяцы, серые подписи отмечают будущие месяцы.
- Просрочка считается по начислениям со сроком оплаты раньше даты среза. К её погашению относятся только платежи, поступившие к этой дате. Линейный график показывает последние 12 календарных месяцев. Для текущего месяца используется сегодняшняя дата, для завершённых месяцев – последний день месяца. Структура задолженности показана на текущую дату.
- Актуальный реестр исключает архивные записи. Левый график объектов считает все добавления за последние 12 календарных месяцев. Архивирование сохраняет договоры объекта. Удаление разрешено, пока у объекта нет договоров, а у договора нет начислений.
- KPI продления, месячный график и кольцевая диаграмма учитывают только фактически действующие договоры с датой окончания. KPI равен сумме интервалов 0–30, 31–90 и 91–180 дней. Кольцевая диаграмма включает также сроки от 181 дня. Месячный график охватывает ближайшие 12 календарных месяцев, включая текущий.
- Сумма по договору справочная и необязательная. Продажа без даты окончания может быть фактически действующей. Такие договоры исключаются из аналитики сроков.

### Реестры и переходы из аналитики

- Нажатие на столбец сроков открывает договоры выбранного месяца. Сектор кольца и строка легенды со стрелкой открывают нужный интервал. Выбор интервала включает статус «Действует» и сортировку по ближайшему окончанию. Явное нажатие «Все» также сбрасывает месяц и статус. При ручном выборе несовместимого статуса очищаются сроки, а выбранный статус сохраняется.
- В «Контрагентах» доступны поиск по имени и ИНН, создание, правка, удаление свободной записи и переход к любому связанному договору. ИНН обязателен. Сервер убирает пробелы и дефисы, сохраняет ведущие нули и проверяет длину. Уникальность обеспечивает PostgreSQL. Электронная почта необязательна и проверяется по формату.
- Карточка договора показывает начисления, оплату, остаток и просрочку. Карточка контрагента суммирует фактические платежи и просрочку по всем его договорам, включая закрытые. Оплата учитывается только по текущую дату включительно.

### Изменения API

- `GET /api/dashboard?year=2025` изменяет только аналитику доходов. Ответ содержит `income_years`. Прежний явный параметр `period` доступен для совместимости.
- `GET /api/contracts` принимает `term`, `expiry_month`, `counterparty_id` и `sort`. `GET /api/contracts/{id}` содержит `finance`.
- `GET /api/counterparties` возвращает количества всех и действующих договоров. `GET /api/counterparties/{id}` также возвращает `finance`. При создании передаются `name`, обязательная строка `tax_id` и необязательный `email`. Поле `email` можно очистить через `PATCH`. Удаление доступно через `DELETE` по тому же адресу.

## Безопасное обновление демонстрационных данных

Все сведения генератора синтетические, включая имена, реквизиты, адреса и договоры. Почта использует домен `.invalid`, а ИНН и кадастровые номера сформированы из условных кодов. Набор включает 100 объектов, 30 контрагентов, 136 договоров и несколько сотен начислений и платежей. Суммы связаны с типом сделки, площадью и периодом действия. История включает несколько последовательных договоров с разрывами, досрочные закрытия и платежи по старым задолженностям.

`backend.seed` заполняет только пустые таблицы выбранной схемы и пропускает посев при наличии записей. Он использует текущую дату Екатеринбурга. Для воспроизводимости можно задать прошедшую опорную дату, например `--as-of 2026-11-28`.

Для полной замены отдельно используется `backend.refresh_demo`. Он заменяет **все строки** пяти прикладных таблиц в `public`. Сначала проверьте, что весь текущий набор синтетический. Одна лишь пометка в названии записи недостаточна. После проверки запишите отпечаток подтверждённого набора:

```powershell
.\.venv\Scripts\python.exe -m backend.refresh_demo --fingerprint
```

Для подтверждения замены именно этого набора подставьте проверенный отпечаток:

```powershell
.\.venv\Scripts\python.exe -m backend.refresh_demo --replace-synthetic <проверенный-SHA256>
```

Скрипт блокирует запись в прикладные таблицы, повторно проверяет отпечаток и создаёт полный архив PostgreSQL в `backups/`. До удаления он проверяет каталог архива, полностью читает архив через `pg_restore` и сохраняет SHA-256. Удаление, новый посев и аудит выполняются в одной транзакции. При ошибке старые строки остаются в базе. Для нестандартного расположения утилит PostgreSQL укажите `--pg-bin` с путём к папке `bin`.

Данные из `public` доступны при обычном запуске на порту 8000. Для проверки на отдельной схеме используйте текущий набор интеграционных тестов либо задайте `PGOPTIONS=-c search_path=<отдельная_пустая_схема>` в отдельном терминале перед `backend.init_db` и `backend.seed`. Схему предварительно создаёт владелец проектной базы. Резервные копии и локальные настройки исключены из Git.

## Исходный код

| Папка | Назначение |
| --- | --- |
| `backend/` | FastAPI, подключение, модели PostgreSQL, Pydantic и команды подготовки базы |

## Автоматические тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют цикл от объекта до оплаты, исторические срезы, граничные сроки продления, поиск, фильтры, удаление, ошибки валидации и защиту от параллельной переплаты. Каждый тест создаёт и убирает собственную схему `qa_…` в проектной базе. Данные приложения в `public` остаются доступны.

На PostgreSQL 15.4 прошли 70 тестов. Они охватывают договоры, фильтры, контрагентов, денежную точность, изменение платежей, пересчёт финансовых периодов, конкурирующие записи и безопасный посев. Браузерные проверки задокументированы в [PROGRESS.md](PROGRESS.md).
