# Учёт муниципального имущества

Локальное приложение для учебной практики. Дашборд показывает поступления, просроченную задолженность, актуальный реестр и договоры на продление. В реестрах можно добавлять и редактировать объекты и договоры. Раздел «Финансы» хранит начисления, частичные платежи и историю оплат.

## Запуск в Windows

Откройте терминал PowerShell в корне проекта, в том числе через **WebStorm → Terminal**. Для запуска нужны Python 3.12 или новее и запущенная служба PostgreSQL 15.

### 1. Окружение и подключение

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Команды вызывают Python напрямую, поэтому активировать окружение и менять PowerShell Execution Policy не требуется. При использовании конфигурации запуска WebStorm выберите `.venv\Scripts\python.exe` как интерпретатор.

Используйте существующий `.env`. Для нового рабочего каталога скопируйте пример и задайте пароль локальной роли, если файла ещё нет.

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
    notepad .env
}
Get-Service postgresql-x64-15
```

Стандартное подключение использует `localhost:5432`, базу `municipal_property` и роль `municipal_user`. Приложение проверяет имя базы и считывает пароль из окружения или `.env`. Пароль со специальными символами передаётся драйверу как отдельный параметр.

Если на другой машине проектная база или роль ещё отсутствуют, выполните следующие команды в `psql` под локальным администратором PostgreSQL. Выполняйте `CREATE ROLE` и `CREATE DATABASE` только для отсутствующей роли или базы. Команда `\password` считывает пароль интерактивно. Существующий пароль менять не нужно.

```powershell
& "$env:ProgramFiles\PostgreSQL\15\bin\psql.exe" -U postgres -d postgres
```

```sql
CREATE ROLE municipal_user LOGIN;
\password municipal_user
CREATE DATABASE municipal_property OWNER municipal_user;
\q
```

Для имеющейся базы подготовка требует прав роли на создание таблиц в `public`. Интеграционные тесты дополнительно требуют права `CREATE` на уровне `municipal_property` для временных схем.

### 2. Схема, демонстрационные данные и сервер

```powershell
.\.venv\Scripts\python.exe -m backend.init_db
.\.venv\Scripts\python.exe -m backend.seed
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

[Открыть приложение](http://127.0.0.1:8000/) · [Документация REST API](http://127.0.0.1:8000/docs)

`init_db` создаёт отсутствующие таблицы и подходит для повторного запуска. Для обновления существующей установки достаточно перезапустить FastAPI с новым кодом. Версия доработки использует прежнюю схему PostgreSQL. Chart.js 4.5.1 входит в локальные ресурсы приложения. Просмотр диаграмм работает без интернета.

Стандартный Swagger UI на `/docs` загружает свои ресурсы через CDN. Схема `/openapi.json` выдаётся локальным сервером.

Списки с оформленными вариантами и плавным открытием и закрытием доступны в браузерах с поддержкой `appearance: base-select`. В остальных браузерах используется системный список. Интерфейс учитывает настройку уменьшенного движения.

## Сквозная проверка через интерфейс

1. В «Объектах» добавьте объект, затем в «Договорах» создайте для него действующий договор со сроком окончания через 20 дней. Выберите или создайте контрагента прямо в форме.
2. В «Финансах» добавьте начисление на 1 000 ₽ по этому договору. Укажите прошлые даты начисления и срока оплаты, чтобы проверить просрочку.
3. Откройте начисление и зарегистрируйте платёж на 300 ₽ сегодняшней датой. В карточке отобразятся история оплаты и остаток 700 ₽.
4. Вернитесь на «Дашборд». Сравните значения с состоянием перед операциями. Доходы вырастут на 300 ₽ за период, в который входит платёж. Просрочка по начислению после платежа составит 700 ₽. Действующий договор добавит 1 к KPI продления.
5. Выбирайте карточки мышью или клавишами Tab и Enter. В каждом режиме меняются заголовки, данные и обе диаграммы. Наведите указатель на точку графика, чтобы увидеть значение.

## Объекты, договоры и начисления

- **Объекты.** Для неархивированного объекта статус «Используется» вычисляется по фактически действующим договорам аренды земли или недвижимости. Без такой аренды объект «Свободен». Карточка и фильтры используют вычисленный статус. Архивирование доступно после прекращения действующих и ожидающих начала договоров всех типов. Восстановление запускает обычный расчёт статуса при чтении. API использует `PATCH /api/properties/{id}` со значением `archived` для архивирования и `available` для восстановления.
- **Договоры.** Завершение и расторжение имеют приоритет над датами. Для записи со статусом `active` будущая дата начала означает «Ожидает начала», прошедшая дата окончания — «Срок истёк», остальные случаи — «Действует». Первый и последний дни входят в срок действия. Сохранённый статус редактируется вручную. В API параметр `state` фильтрует фактическое состояние, а `status` — сохранённый статус.
- **Архивные связи.** Архивный объект нельзя выбрать для нового договора или переноса. Изменение статуса или дат старого договора, которое сделает его действующим или ожидающим начала, требует восстановления объекта. Историческая связь и финансовые записи доступны при просмотре. Для ранее сохранённой несовместимой пары доступны правки справочных полей и завершение договора, а активация и продление требуют исправления пары.
- **Совместимость.** Аренда земли допускает только земельные участки, аренда недвижимости — здания и нежилые помещения. Продажа и прочие договоры допускают все категории. Категорию объекта можно изменить после завершения или расторжения несовместимых связанных договоров. Для договора со статусом записи `active` и истёкшей датой окончания сначала завершите его вручную.
- **Начисления и платежи.** Начисление можно изменить или удалить до первого зарегистрированного платежа. Допустимая дата платежа лежит между датой начисления и сегодняшней датой включительно. Частичная оплата сохраняется. Прежние платежи с будущими датами остаются в истории и ограничивают возможность нового платежа в пределах начисления, а в оплаченные суммы, доходы и просрочку входят с даты поступления.

## Правила расчёта

- Дата среза берётся в часовом поясе `Asia/Yekaterinburg`. Доходы суммируются за выбранный период. Последние 12 месяцев включают текущий месяц по дату среза. Для периода «Всё время» история начинается с первого начисления или платежа по дату среза.
- Просрочка считается по начислениям со сроком оплаты раньше даты среза. В остаток входят только платежи, поступившие к этой дате. Для текущего месяца используется сегодняшняя дата, для завершённых месяцев — последний день месяца. Структура задолженности всегда показана на текущую дату.
- Актуальный реестр исключает архивные записи. Левый график объектов считает все добавления за последние 12 календарных месяцев. Архивирование сохраняет договоры объекта. Удаление разрешено, пока у объекта нет договоров, а у договора нет начислений.
- KPI продления, месячный график и кольцевая диаграмма учитывают только фактически действующие договоры с датой окончания. KPI равен сумме интервалов 0–30, 31–90 и 91–180 дней. Кольцевая диаграмма включает также сроки от 181 дня. Месячный график охватывает ближайшие 12 календарных месяцев, включая текущий.
- Сумма по договору справочная и необязательная. Продажа без даты окончания может быть фактически действующей. Такие договоры исключаются из аналитики сроков.

## Безопасное обновление демонстрационных данных

Генератор заполняет только пустую схему и пропускает посев, если в любой из таблиц уже есть записи. Новый набор содержит 100 объектов, 24 контрагента, 124 договора, 310 начислений и около 310 платежей. Для фиксированного набора можно передать `--as-of 2026-11-27`. Опорная дата должна быть не позже сегодняшней.

Признаки старых демонстрационных записей могли сохраниться после пользовательских правок. Для безопасного просмотра нового набора сделайте резервную копию существующей схемы и вручную создайте отдельную пустую схему. Команды рассчитаны на стандартные настройки подключения из примера. При необходимости подставьте хост, порт и роль из своего окружения. PostgreSQL запросит пароль интерактивно.

```powershell
$pgBin = "$env:ProgramFiles\PostgreSQL\15\bin"
$backup = "municipal_property-public-$(Get-Date -Format 'yyyyMMdd-HHmmss-fff').dump"
& "$pgBin\pg_dump.exe" -h localhost -p 5432 -U municipal_user -W -d municipal_property --schema=public --format=custom --file=$backup
if ($LASTEXITCODE -ne 0) { throw 'Резервная копия не создана.' }
& "$pgBin\pg_restore.exe" --list $backup
if ($LASTEXITCODE -ne 0) { throw 'Не удалось прочитать каталог резервной копии.' }

& "$pgBin\psql.exe" -h localhost -p 5432 -U municipal_user -W -d municipal_property -X -v ON_ERROR_STOP=1 -c 'CREATE SCHEMA municipal_demo'
if ($LASTEXITCODE -ne 0) { throw 'Выберите новое имя для демонстрационной схемы.' }

$previousOptions = $env:PGOPTIONS
try {
    $env:PGOPTIONS = '-c search_path=municipal_demo'
    .\.venv\Scripts\python.exe -m backend.init_db
    if ($LASTEXITCODE -ne 0) { throw 'Ошибка создания таблиц.' }
    .\.venv\Scripts\python.exe -m backend.seed
    if ($LASTEXITCODE -ne 0) { throw 'Ошибка заполнения демонстрационной схемы.' }
    .\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8001
} finally {
    $env:PGOPTIONS = $previousOptions
}
```

Демонстрационный сервер открывается на порту 8001. Для следующего нового набора укажите другое имя схемы в обеих командах. Обычный сервер без этого параметра использует прежние данные.

## Автоматические тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют цикл от объекта до оплаты, исторические срезы, граничные сроки продления, поиск, фильтры, удаление, ошибки валидации и защиту от параллельной переплаты. Каждый тест создаёт и убирает собственную схему `qa_…` в проектной базе. Данные приложения в `public` остаются доступны.

На PostgreSQL 15.4 прошли 27 тестов, в том числе сценарии обновлённых статусов, архивирования и конкурирующих операций. Браузерные проверки задокументированы в [PROGRESS.md](PROGRESS.md).
